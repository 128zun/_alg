我們以題目中提到的經典文字比對核心——最長公共子序列（Longest Common Subsequence, LCS）來作為範例。LCS 是版本控制工具（如 git diff）底層演算法的重要基礎。以下將分別介紹如何使用 動態規劃（Dynamic Programming） 與 非動態規劃（純遞迴法） 來解決這個問題，並進行原理、複雜度與優缺點的比較。選擇的問題：最長公共子序列（LCS）給定兩個字串（例如字串 $A$ 和字串 $B$），尋找它們最長且保持相對順序的相同子字串長度。例如：字串 $A$ 為 ABCBDAB，字串 $B$ 為 BDCABA，其 LCS 長度為 4（對應子序列如 BCBA 或 BDAB）。1. 動態規劃解法（Dynamic Programming）原理動態規劃的核心思想是將大問題拆解為重疊的小問題，並透過表格（Table）記錄子問題的解，避免重複計算。
我們定義一個二維陣列 dp[i][j]，代表「字串 $A$ 的前 $i$ 個字元」與「字串 $B$ 的前 $j$ 個字元」的最長公共子序列長度。遞推關係式如下：當 $A[i] == B[j]$ 時：dp[i][j] = dp[i-1][j-1] + 1（代表當前字元相符，長度加 1）。當 $A[i] \neq B[j]$ 時：dp[i][j] = max(dp[i-1][j], dp[i][j-1])（代表取「略過 $A$ 的當前字元」或「略過 $B$ 的當前字元」的最大值）。複雜度分析時間複雜度：$O(m \times n)$，其中 $m$ 和 $n$ 分別為兩個字串的長度。因為需要填滿大小為 $m \times n$ 的二維表格。空間複雜度：$O(m \times n)$（若進行空間優化，僅保留前一行或滾動陣列，可降至 $O(\min(m, n))$）。2. 非動態規劃解法（純遞迴法 / Naive Recursion）原理不使用任何記憶化或表格儲存，直接依據 LCS 的數學定義寫出遞迴函數。
當比對到兩個字串的尾端字元：若字元相同，則回傳 1 + 遞迴計算(A去掉尾端, B去掉尾端)。若字元不同，則回傳 max(遞迴計算(A去掉尾端, B), 遞迴計算(A, B去掉尾端))。這種方法完全依靠函式呼叫堆疊（Call Stack）來遍歷所有可能的路徑，會產生大量的重複子問題（Overlapping Subproblems）。複雜度分析時間複雜度：$O(2^{m+n})$（指數級別）。在最壞情況下，每個狀態都會分叉成兩個子狀態，隨著字串長度增加，計算量會呈爆炸性成長。空間複雜度：$O(m + n)$。雖然不需要額外的二維表格，但遞迴呼叫的深度最多為 $m + n$，會消耗系統堆疊空間。3. 兩者比較與總結比較項目動態規劃法 (DP)非動態規劃法 (純遞迴)核心機制由底向上（Bottom-Up）填表，記錄並重複利用歷史結果由頂向下（Top-Down）盲目遞迴，重複計算相同子問題時間複雜度$O(m \times n)$（多項式時間，極高效）$O(2^{m+n})$（指數時間，極慢）空間複雜度$O(m \times n)$（需儲存表格，可優化）$O(m + n)$（僅需堆疊空間）實際應用價值適用於任何長度的真實檔案比對（如 git diff）僅適用於極短字串（通常長度大於 20 就會導致程式當機或無限等待）總結：在處理文字差異比對這類具有「最佳子結構」與「重疊子問題」特性的問題時，非動態規劃的純遞迴法會陷入無止境的重複計算。而動態規劃透過空間換取時間的策略，是讓文字比對工具能夠在毫秒內處理數萬行程式碼關鍵所在。
